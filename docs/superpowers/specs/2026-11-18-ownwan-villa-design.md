## 1. 무엇을 왜 만드나

같이 오운완(오늘 운동 완료)하기로 한 사람들이 **빌라 하나에 입주**해서, 매일 운동 인증 사진과 루틴을 올리고, 받은 포인트로 **자기 방을 운동 종목에 맞는 가구로 꾸미며**, 꾸준히 할수록 **높은 층으로 올라가 펜트하우스를 차지**하는 웹앱이다.

- **누구를 위한 것인가** : 운동을 꾸준히 하고 싶은 사람들 (헬스, 필라테스, 러닝, 클라이밍, 주짓수, 태권도 등)
- **왜** : 혼자 하면 끊기는 운동을, 친구들과 한 건물에 사는 느낌과 눈에 보이는 보상(불 켜진 방, 가구, 층수, 펜트하우스)으로 매일 이어가게 한다
- **운영 목표** : 실제 사람을 모아 운영하는 서비스. 잘되면 후원을 받고 회사 서비스로 키운다 **[확정]**
- **비용 조건** : 지금은 무료 호스팅 범위 안에서만 운영한다 **[확정]**

### 4.2 인증과 포인트

| 항목 | 포인트 (예시) |
|---|---|

- **[확정 — 기획자 결정, 2026-11-19]** 포인트는 **인증 기록 하나에 한 번**만 준다. 빌라 여러 곳에 올려도 곱하지 않고, 나중에 "다른 빌라에도 올리기"를 해도 더 주지 않는다. 포인트 · 가구 · 옷 · 캐릭터는 사람에게 하나뿐이고(빌라마다 따로 없다), 방 꾸미기(가구 배치)는 어느 빌라에서나 같다
- **[제안]** 인증 사진은 그날 촬영 여부를 검사하지 않는다. 첫 버전에서는 유사도 비교와 빌라 내 신고로 대응한다

### 4.3 층
- 7일 연속 인증 달성 시 한 층 올라간다 **[확정]**
- 연속 기록이 끊기면 한 층 내려간다 **[확정]**
- **[제안]** 세부 규칙
  - 입주 시 1층에서 시작한다
  - 연속 기록 7일, 14일, 21일… 달성 시점마다 +1층
  - 인증을 하루 빠뜨리면 연속 기록은 0이 되고 즉시 -1층
  - 그 뒤로도 인증하지 않으면 7일마다 1층씩 더 내려간다 (오래 쉬면 계속 내려감)
  - 최저층은 1층
  - 층에는 상한이 없다
- 7일째 인증을 하면 그 즉시 한 층 올라간 것으로 보인다(자정 정산 때 확정). 내려가는 것은 하루가 끝나야 알 수 있어 자정에 반영한다. **[확정 — 기획자 결정]**

**층 · 연속 기록은 빌라마다 [확정 — 기획자 결정, 2026-11-19]**
- 층과 층을 정하는 연속 기록은 **입주 기록(사람 × 빌라)마다** 따로 센다. 위 규칙은 그대로이고, "인증한 날"만 빌라마다 다르게 본다
- **빌라 V에서 인증한 날** = 그날(한국 시간) V에 올라간, 지우지 않은 · 중복이 아닌 사진 인증이 하나 이상 있는 날. 인증할 때 V를 골랐거나, 같은 날 "다른 빌라에도 올리기"로 V에 올린 경우다
- 입주 기록마다 `streak`(V에서 인증한 날 연속 일수), `missRun`(V에서 인증하지 않은 날 연속 일수), `floor`, `floorReachedAt`를 둔다. 자정 정산 때 입주 기록마다:
  - V에서 인증한 날 : streak + 1, missRun = 0. streak가 7의 배수가 되면 floor + 1, floorReachedAt = 정산 시각
  - 인증하지 않은 날 : streak = 0, missRun + 1. missRun % 7 == 1 이고 floor > 1 이면 floor − 1 (끊긴 날 바로 −1, 그 뒤 쉬면 8일째 · 15일째 … 마다 −1). 최저 1층
  - 그날이 끝난 뒤 입주한 빌라는 그날 정산하지 않는다 (밀린 날을 몰아 정산할 때). 정산은 지금처럼 날짜 선점(token)으로 한 번만, 밀리면 최대 7일까지 오래된 날부터
- 화면 · 순위의 층 = floor, 단 오늘 V에 올렸고 (streak + 1) % 7 == 0 이면 floor + 1 (오늘 7일째). 연속 기록 표시 = streak + (오늘 V에 올렸으면 1)
- **입주하면 그 빌라에서는 1층 · 연속 0일에서 시작**한다(입주 전 날은 그 빌라에 올린 날이 아니므로). 다른 빌라의 층은 바뀌지 않는다
- **사용자 연속 기록**(프로필 · 방의 "연속 n일", 사용자 축하)은 지금과 같은 뜻: 어느 빌라든(빌라가 없어도) 사진 인증한 날. 빌라에 올리는지와 상관없다
- 예) A · B 두 곳에 살며 7일 동안 A에만 올리면: A는 7일째에 +1층, B는 첫날 −1층(최저 1층) 뒤 그대로, 8일째에도 안 올리면 B는 또 −1층. 사용자 연속 기록은 7일
- 기존 데이터 : 0010 마이그레이션이 지금 사는 빌라의 입주 기록에 사용자 연속 기록 · 쉰 날을 그대로 옮겨, 빌라 1곳에 살던 사람은 층이 예전과 똑같이 움직인다

### 4.4 펜트하우스
- 빌라에서 1등 한 명만 산다 **[확정]**
- **[제안]** 1등 판정 순서
  1. 층이 가장 높은 사람
  2. 층이 같으면 현재 연속 기록이 긴 사람
  3. 그것도 같으면 그 층에 먼저 도달한 사람
- **[확정 — 기획자 결정]** 1등은 인증·삭제·입주·나가기 때 바로, 그리고 자정 정산 때 다시 계산한다. 같은 층이면 오늘 인증까지 포함한 연속 기록으로 비교한다. 밀려난 사람은 자기 층의 방으로 돌아간다
- **[확정 — 기획자 결정, 2026-11-19]** 1등은 빌라마다 그 빌라의 층 · 연속 기록(4.3 "빌라마다")으로 정한다. 오늘 그 빌라에 올라간 사진이 있으면 오늘 7일째 층까지 친다. 오늘 올라간 층의 "도달 시각"은 그 빌라에 첫 사진 인증이 올라간 시각(나중에 올렸으면 올린 시각). 인증 · 다른 빌라에도 올리기 · 삭제 때는 그 기록이 올라간 빌라만 다시 계산한다
- **[제안]** 펜트하우스에는 전용 장식(샹들리에, 통유리창 등)이 고정되어 있다. 개인 가구는 사람을 따라 이사한다
- **[제안]** 입주민이 1명뿐이어도 그 사람이 펜트하우스에 산다

## 5. 기능 상세 (첫 버전)

### 5.1 회원가입 · 로그인 · 계정 복구 [확정]

받는 정보는 **아이디, 비밀번호, 닉네임**뿐이다. 이메일 · 전화번호는 받지 않는다. (카카오로 가입하면 아이디 · 비밀번호 대신 카카오 회원번호 — 아래 "카카오 로그인 · 가입")

**회원가입 필드**
- 아이디 : 텍스트입력, 빈값, -, 필수 (영문 소문자·숫자 4~16자, 중복 확인)
- 비밀번호 : 비밀번호입력, 빈값, -, 필수 (8자 이상)
- 비밀번호 확인 : 비밀번호입력, 빈값, -, 필수
- 닉네임 : 텍스트입력, 빈값, -, 필수 (빌라에서 보이는 이름, 2~10자)
- 만 14세 이상 확인 : 체크박스, 미체크, -, 필수
- 이용약관 · 개인정보 처리방침 동의 : 체크박스, 미체크, -, 필수

**복구 코드 (기본 수단)**
- 가입 완료 시 복구 코드(예: `K7QM-2XPA-9RTE-W4LN`)를 한 번만 보여준다. 복사 · 이미지 저장 버튼 제공
- "복구 코드를 저장했어요" 체크 후에만 다음 단계로 이동
- 비밀번호 분실 시 아이디 + 복구 코드 입력 → 새 비밀번호 설정 → 새 복구 코드 발급 (기존 코드는 폐기)
- 로그인 상태에서 설정 화면에서 복구 코드를 재발급할 수 있다 (재발급 시 기존 코드 폐기)
- 서버에는 복구 코드를 해시로만 저장한다

**방장 확인 (보조 수단)**
1. 로그인 화면 "복구 코드도 없어요" → 아이디 입력
2. 해당 사용자가 사는 빌라의 방장에게 복구 요청 알림
3. 방장이 본인 여부를 직접(빌라 밖 연락 수단으로) 확인 후 승인
4. 승인 후 24시간 대기. 대기 중 원래 사용자가 로그인하면 요청 자동 취소
5. 24시간 후 요청자가 아이디 + 복구 요청 번호로 새 비밀번호 설정
- 요청자가 방장이면, 빌라에 가장 오래 산 입주민이 확인한다
- **[제안]** 빌라에 속하지 않은 사용자(입주 전)는 방장 확인을 쓸 수 없다
- **[확정 — 2026-11-19, 여러 빌라에 살기에 맞춰 개발자가 정한 규칙]** 빌라 여러 곳에 살면 **가장 먼저 입주한(가장 오래 산) 빌라 한 곳**에서만 확인한다: 그 빌라의 방장(요청자가 방장이면 그 빌라에 가장 오래 산 입주민). 확인해 줄 수 있는 사람을 늘리지 않으려는 것이다. 승인할 때 그 빌라를 적어 두고, 완료할 때 그 빌라에 아직 살아야 한다

**카카오 로그인 · 가입 [확정 — 기획자 결정, 2026-11-19]**
- 카카오에서는 **회원번호(id)만** 받는다. 이메일 · 전화번호 · 프로필 사진 · 닉네임은 받지 않고, 동의 항목(scope)도 요청하지 않는다. 카카오 토큰은 저장하지 않는다 (회원번호를 읽은 뒤 버린다)
- 랜딩 · 로그인 · 가입 화면에 **[카카오로 시작하기]** 버튼 (카카오 노란색 #FEE500, 검은 글자, 말풍선 심볼). 아이디 · 비밀번호 가입과 로그인은 그대로 둔다
- 처음 온 카카오 회원번호 → **닉네임 정하기** (닉네임 규칙은 일반 가입과 같음 + 만 14세 이상 · 약관 동의 체크) → 계정 생성 → 일반 가입과 같은 다음 단계(빌라 만들기 · 초대 링크로 입주 → 종목 · 캐릭터)
- 카카오로만 가입한 계정은 **복구 코드가 없다**. 카카오로 다시 로그인하는 것이 복구 수단이다. 복구 코드 · 방장 확인 · 비밀번호 로그인 · 비밀번호 변경은 "카카오로 가입한 계정이에요. 카카오로 로그인하면 돼요"로 안내한다
- 이미 아는 카카오 회원번호 → 로그인 (비밀번호 로그인과 같은 세션, 새 세션 발급. 진행 중인 방장 확인 요청은 취소)
- 기존 아이디 · 비밀번호 계정: 설정 → **카카오 연결** 칸. 세 가지 상태
  - 연결 안 됨: [카카오 연결하기]. 그 카카오 계정이 다른 계정에 연결돼 있으면 "이 카카오 계정은 다른 오운완빌라 계정에 연결돼 있어요"
  - 연결됨: [연결 해제] (비밀번호가 있는 계정만)
  - 카카오로만 가입: 해제 버튼 없이 설명만 ("카카오로 가입한 계정이라 … 연결은 해제할 수 없어요"). 비밀번호 변경 · 복구 코드 칸은 숨긴다
- 한 계정에 카카오 계정 하나, 한 카카오 계정은 한 계정에만 연결된다
- 탈퇴하면 카카오 연결도 함께 지운다 (같은 카카오 계정으로 새로 가입할 수 있다)
- 구현 메모 (개발): 카카오 전용 계정은 users 표를 고치지 않고 `password_hash = '!kakao-only'`(어떤 비밀번호로도 맞지 않음), 숨긴 아이디 `kakao_` + 무작위 20자(가입 아이디 규칙에 `_`가 없어 겹치지 않음)로 표현한다. 연결은 `user_identities(provider, provider_user_id, user_id)` 표 (migrations/0011_kakao.sql). 로그인 시작 때 state 를 짧은 쿠키(10분, httpOnly · SameSite=Lax · Secure)와 D1(해시)에 두고 콜백에서 한 번만 쓴다. 닉네임을 정하기 전까지는 회원번호만 10분짜리 대기 표에 둔다
- 키(KAKAO_REST_API_KEY · KAKAO_CLIENT_SECRET)는 GitHub Actions secret → 배포 때 Worker secret 으로 넣는다. 키가 없으면 "카카오 로그인을 준비 중이에요"로 안내한다
- Redirect URI: `https://ownwan-villa.silverbin2598.workers.dev/api/auth/kakao/callback`

### 5.2 빌라

- 정원 20명으로 고정 **[확정 — 기획자 결정, 2026-11-18]** (→ 아파트로 승격하면 50명, 5.12 **[제안 — 기획자 확인 필요, 2026-11-20]**) (기존 10명에서 확대. 기존 빌라와 새 빌라 모두 적용. 빈방은 한 줄만 그리고 나머지는 "빈방 n개"로 접어 보여 준다)
- 입주 경로 2가지 **[확정]**
  - 초대 링크 : 방장이 만든 링크로 입주
  - 빈방 모집 : 빈방에 모집 글을 올려 같이 운동할 사람을 모음
- 빌라 이름은 방장이 정한다 **[확정]**
- **[제안]** 방장 권한 : 빌라 이름 변경, 초대 링크 생성 · 재생성, 빈방 모집 글 작성 · 입주 신청 승인(→ 아래 빈방 모집에서 확정), 도시 공개 설정(→ 5.7에서 확정), 계정 복구 승인
- **[제안]** 강퇴, 수동 방장 위임, 빌라 해체는 첫 버전에서 제외 (다음 버전에서 정의)

**빌라 나가기 · 옮기기 [확정]**
- 첫 버전에 "빌라 나가기"를 넣는다
- ~~사용자는 빌라 1곳에만 산다~~ → 아래 "여러 빌라에 살기"로 바뀌었다 **[확정 — 기획자 결정, 2026-11-19]**
- 빌라를 나가거나 새로 들어가도 **연속 기록(사용자), 포인트, 가구, 캐릭터는 그대로이고, 새 빌라에서는 층이 1층부터 시작한다**
  - 이유 : 내가 쌓은 습관은 남기고, 새 빌라의 순위는 흔들지 않는다
  - 따라서 사용자 연속 기록 · 포인트 · 가구는 사용자에게, 층과 층을 정하는 빌라 연속 기록은 빌라 입주 기록에 붙는다 (4.3)
- **[제안]** 빌라를 나가면 그 방은 빈방이 되고, 인증 사진 · 루틴은 원래 빌라에서 더 이상 보이지 않는다
- **[제안]** 빌라가 없는 상태에서도 인증은 할 수 있고 연속 기록이 이어진다. 층은 없다
- **[제안]** 방장이 나가면 그 빌라에 가장 오래 산 입주민이 자동으로 방장이 된다. 마지막 한 명이 나가면 빌라는 도시에서 사라진다
- **[제안]** 나가기 전에 "층은 1층부터 다시 시작해요" 확인 화면을 보여준다

**여러 빌라에 살기 [확정 — 기획자 결정, 2026-11-19]**
- 한 사람이 **빌라 3곳까지** 함께 산다 (`MAX_VILLAS_PER_USER = 3`). 직접 만든 빌라도 센다. 초대 링크로 입주하면(나중에 빈방 모집도) 지금 빌라를 떠나지 않고 한 곳이 더해진다
- 3곳이 다 차면 입주 · 만들기 화면에서 "빌라는 3곳까지 살 수 있어요. 한 곳을 나가면 들어올 수 있어요"를 보여 주고 입주 버튼은 없다. 서버도 입주 · 만들기 문장 안에서 사는 빌라 수를 세어 막는다(동시에 눌러도 넘지 않는다)
- 한 빌라를 나가도 다른 빌라에는 아무 영향이 없다. 입주 금지 · 정원 20명 · 방장 일(내보내기 · 넘기기 · 해체)은 빌라마다 그대로
- 탈퇴하면 사는 빌라 모두에서 나간다(빌라마다 방장 승계 · 해체 규칙대로)
- 빌라 화면 위쪽에 **빌라 바꾸기 탭**(빌라 이름, 오늘 그 빌라에 올렸으면 작은 불)과 3곳보다 적으면 [+](빌라 만들기). 고른 빌라는 기기에 기억한다. 빌라 화면 주소는 `/villa/:id`, 예전 주소 `/villa`는 마지막으로 본 빌라(없으면 가장 먼저 입주한 빌라)로 보낸다. 빌라가 1곳이면 탭은 없다
- 설정의 빌라 메뉴(방장 메뉴 · 도시 지도 공개 · 빌라 나가기)는 설정 안 빌라 탭으로 고른 빌라에 대해 보여 준다
- 축하 · 알림(층 오름 · 내림, 펜트하우스, 새 이웃, 방장 바뀜)은 빌라마다 따로 생기고, 빌라 2곳 이상에 사는 사람에게는 빌라 이름을 붙여 보여 준다 ("14일 연속! 에이빌라 3층으로 올라왔어요"). 같은 날 두 빌라에서 각각 축하할 수 있다. 사용자 연속 7일 축하는 같은 숫자의 층 오름 축하가 함께 생기면 겹쳐 보내지 않는다

**빈방 모집 · 입주 신청 [확정 — 기획자 결정, 2026-11-19]** (여러 빌라에 살기 다음에 만들었다. 빈방 모집으로 들어와도 3곳 제한을 센다)

*모집 글 (설정 → 고른 빌라의 "빈방 모집", 도시 지도 공개 스위치 아래)*
- 빈방 모집 : 스위치, 꺼짐, 켬/끔, 방장만
- 한 줄 소개 : 한 줄 글, 빈칸, 60자까지(앞뒤 공백 · 겹친 공백 정리), 선택 (비면 "같이 운동할 이웃을 찾고 있어요")
- 함께하고 싶은 종목 : 여러 개 고르기(칩), 안 고름, 헬스/필라테스/러닝/클라이밍/주짓수/태권도(5.3의 종목 그대로, 다른 선택지는 없다), 선택 (안 고르면 "종목 상관없음")
  - 신규입력 : 방장이 스위치를 켜면 소개 · 종목 칸이 열리고 [모집 시작하기]로 저장 (저장 전에 끄면 그냥 접힌다)
  - 수정 : 모집 중이면 소개 · 종목을 고치고 [저장]. 스위치를 끄면 바로 모집이 끝나고, 받은 신청이 있으면 "모집을 끄면 받은 신청 n개가 취소돼요" 확인 후 끈다
  - 읽기전용 : 방장이 아닌 입주민은 지금 모집 글(소개 · 종목 · 빈방 n개)만 보거나 "지금은 빈방을 모집하지 않아요"
- 모집은 **도시 지도에 공개한 빌라만** 켤 수 있다. 공개 안 한 빌라의 방장에게는 "지도에 공개하면 모집할 수 있어요" + [지도에 공개하기]. 지도에서 내리면 모집도 꺼진다
- 정원 20명이 차면(초대 링크 입주 · 신청 승인 모두) 서버가 모집을 끈다. 꽉 찬 빌라는 모집을 켤 수 없고 지도에도 모집 글이 나오지 않는다
- 방장 권한은 빌라마다: 방장을 넘기면 새 방장이 모집 글과 받은 신청을 본다

*입주 신청 (도시 지도 → 모집 중인 빌라 카드 → [입주 신청])*
- 로그인한 누구나 신청할 수 있다. 다른 빌라에 살아도 된다. 단,
  - 빌라 3곳에 살고 있으면 "빌라는 3곳까지 살 수 있어요. 한 곳을 나가면 신청할 수 있어요", 버튼 없음
  - 이미 그 빌라 입주민이면 "우리 빌라 모집 글이에요", 버튼 없음
  - 그 빌라에서 내보내진 사람이면 "이 빌라에는 신청할 수 없어요"(내보낸 일은 말하지 않는다), 버튼 없음
- 방장에게 한마디 : 여러 줄 글, 빈칸, 100자까지, 선택
- **한 사람은 한 번에 한 곳에만** 기다리는 신청을 둔다(DB 유일 색인. 동시에 두 곳을 눌러도 하나만 들어간다). 다른 곳에 신청 중이면 "OO에 보낸 신청을 기다리는 중이에요. 신청은 한 번에 한 곳만 할 수 있어요" + [그 신청 취소]
- 신청한 사람은 도시 위쪽 한 줄 · 그 빌라 카드 · 설정 "내 입주 신청"에서 자기 신청 상태(기다리는 중, n일 뒤 만료)를 보고 [신청 취소]할 수 있다
- 신청은 **7일** 동안 답이 없으면 만료된다(읽을 때 만료로 보고, 매일 크론이 만료로 바꾸며 "입주 신청이 7일이 지나 만료됐어요" 알림). 끝난 신청 기록은 30일 뒤 지운다

*방장의 승인 · 거절 (설정 → 입주민 관리 → 입주 신청)*
- 방장에게 "OO 님의 입주 신청이 왔어요" 알림(토스트). 설정 배지에도 센다
- 목록 한 줄: 캐릭터 얼굴, 닉네임, 연속 기록(사용자), 종목, 신청한 날, 한마디, [승인] [거절]. 오래된 신청부터
- **승인하면 바로 입주한다**(신청한 사람이 다시 확인하지 않는다). 초대 링크 입주와 같은 길: 그 빌라 1층부터, 새 이웃 알림, 1등 다시 계산. 신청한 사람에게 "입주 신청이 승인됐어요! OO에 입주했어요" 축하 카드
- 승인하는 순간 한 문장 안에서 다시 본다: 신청이 아직 기다리는 중이고 7일 안, 승인하는 사람이 아직 해체 안 된 빌라의 방장, 빈방 있음, 입주 금지 아님, 아직 입주민 아님, 빌라 3곳 미만. 아니면 승인되지 않고 이유를 알려 준다(꽉 참 → 모집을 끄고 기다리던 신청 모두 취소 / 3곳 → 그 신청 취소 / 만료 / 방장이 바뀜 → 신청은 그대로 두어 새 방장이 본다). 두 번 눌러도 입주는 한 번
- 거절하면 이유 없이 신청한 사람에게 "이번에는 OO에 함께하지 못하게 됐어요. 다른 빌라도 둘러봐요" 카드. 거절한 신청은 목록에 다시 나오지 않는다. 거절은 입주 금지가 아니라 다시 신청할 수 있다
- 빌라 일과 신청: 모집 끔 · 지도에서 내림 · 해체(마지막 입주민이 나간 경우 포함) → 기다리던 신청 취소 + 신청한 사람에게 부드러운 알림. 내보내기 → 그 사람의 그 빌라 신청은 거절. 초대 링크로 먼저 들어오면 그 빌라 신청은 끝. 탈퇴하면 그 사람의 신청 기록을 지운다
- 보이는 범위: 도시 카드에는 모집 글(소개 · 종목 · 빈방 수)과 지금 있는 숫자만. 신청한 사람의 닉네임 · 한마디 · 연속 기록은 그 빌라 방장만, 신청 상태는 신청한 본인만 본다

  - 수정 : 설정 화면에서 변경 가능
  - 읽기전용 : 다른 입주민의 방 상세에서 표시만

### 5.4 인증 · 루틴

- 사진 업로드 (1장 이상), 루틴 글 (선택)
- 인증 사진과 루틴은 **같은 빌라 사람들끼리만** 본다 **[확정]**

**올릴 빌라 고르기 [확정 — 기획자 결정, 2026-11-19]**
- 인증은 **고른 빌라에만** 올라간다. 올릴 빌라 필드
  - 올릴 빌라 : 체크박스(여러 개), 사는 빌라 모두 체크, 내가 사는 빌라 목록, 빌라에 살면 1곳 이상 필수
    - 신규입력 : 모두 체크된 채로 시작, 끄고 켤 수 있다. 마지막 하나는 끌 수 없다("빌라를 하나 이상 골라야 해요")
    - 수정 : 오늘 이미 올린 뒤에도 다음 사진 · 루틴을 올릴 빌라를 바꿀 수 있다. 오늘 올린 빌라에는 "오늘 올렸어요" 표시
    - 읽기전용 : 빌라가 1곳이면 체크박스 없이 "OO에 올라가요". 빌라가 없으면 "빌라 없이 내 기록으로만 남아요"(지금처럼 인증 · 연속 기록은 된다)
- 그 빌라에만 효과가 있다: 방 불, 게시판 · 사진 · 루틴이 보이는 범위, 층 · 펜트하우스, 도시 지도의 불 켜진 창, 그 빌라 축하
- **보이는 범위** : 기록은 그 기록이 올라간 빌라 중 한 곳에 작성자와 보는 사람이 **둘 다 지금 사는** 경우에만 보인다(본인은 늘 본다). 다른 빌라에만 함께 사는 사람은 볼 수 없다. 응원 · 댓글 · 신고도 같은 범위. 빌라 화면에서 방 · 게시판을 열면 그 빌라에 올린 기록만 보인다
- **다른 빌라에도 올리기** : 오늘 어느 빌라엔가 사진 인증을 올렸고 아직 안 올린 빌라가 있으면, 인증 화면에 "다른 빌라에도 올리기"가 보인다. 누르면 **오늘(한국 시간) 올린 내 사진 · 루틴 모두**를 그 빌라에도 붙인다. 같은 날 안에만 되고, 포인트는 더 주지 않는다. 그 빌라에서 오늘 처음 불이 켜지면 그 빌라 층 · 1등 · 축하가 바로 반영된다. 다른 빌라에만 올린 날 빌라 화면의 인증 버튼은 [이 빌라에도 올리기]가 된다
- 빌라에서 내리기는 없다. 기록을 지우면(작성자 또는 그 기록이 올라간 빌라 중 작성자가 사는 빌라의 방장) 올라간 **모든 빌라에서** 사라진다
- 예전 화면(빌라를 보내지 않는 요청)으로 올리면 사는 빌라 모두에 올린다

**루틴 수정 [제안 — 2026-11-20, 기획자 질문 "루틴 수정이 없어?"]**
- **[제안]** 올린 루틴 글은 **작성자 본인만** 고칠 수 있다. 날짜 제한 없음(어제 · 지난주 글도 된다). 사진 인증은 고칠 수 없다
- **[제안]** 글 규칙은 쓸 때와 같다: 앞뒤 공백을 뺀 1~1000자
- **[제안]** 고쳐도 **포인트 · 날짜 · 올린 빌라 · 응원 · 댓글은 그대로**다. 예전 글은 남기지 않는다(마지막 고친 시각만 남김)
- **[제안]** 고친 글에는 날짜 옆에 "수정됨"이 붙는다 (방 벽 게시판 · 전체 기록 모두, 보는 사람 누구에게나)
- **[제안]** 신고로 가려진 글도 작성자는 고칠 수 있지만, 고쳐도 계속 가려져 있다 (화면에서는 가려진 글에 [수정]을 보여 주지 않는다)
- 루틴 글 필드 (전체 기록 화면의 메모지)
  - 보기 : 메모지에 글 · 날짜(고쳤으면 "· 수정됨"). 내 루틴이면 하트 · 댓글 옆에 [수정]
  - 수정 중 : [수정]을 누르면 메모지 아래 한 줄 전체에 글 상자가 열린다. 지금 글이 들어 있고 글자 수 n/1000, [취소] [저장]. 글이 비었거나 바뀌지 않았으면 [저장]을 누를 수 없다. 저장하면 바로 메모지가 바뀌고 닫히며, 실패하면 원래 글로 되돌리고 고치던 글과 안내 문구로 다시 연다
  - 읽기전용 : 다른 사람의 루틴 · 사진에는 [수정]이 없다
- **구현 메모 (개발)**: migrations/0016_cert_edit.sql (`certs.edited_at` 열 추가, 운영 데이터에 안전). API `PATCH /api/certs/:id` 본문 `{ body }` → 200 `{ ok, body, editedAt }`. 없음 · 지움 · 볼 수 없음 404, 같은 빌라지만 작성자가 아님 403, 사진 409, 글 1~1000자 아님 400. 게시판 응답(`GET /api/users/:id/board`)은 고친 루틴에만 `editedAt`. 화면 src/web/components/RoutineEdit.tsx, src/web/pages/RoomBoard.tsx

**방 게시판 [확정]**
- 모든 방의 **왼쪽 벽은 늘 게시판**이다. 가구를 놓는 자리가 아니라 고정 요소다
- 올린 오운완 사진과 루틴이 게시판에 붙는다
- **[제안]** 게시판에는 최근 것부터 사진은 폴라로이드처럼, 루틴은 메모지처럼 붙는다. 방 화면에서는 최근 몇 개만 보이고, 게시판을 누르면 전체 기록을 날짜순으로 본다
- **[제안]** 같은 빌라 입주민은 다른 사람 방에 들어가 그 사람의 게시판을 볼 수 있다

**신고 [제안]**
- 같은 빌라 입주민이 부적절한 사진을 신고할 수 있다
- 3명이 신고하면 사진이 자동으로 가려지고, 방장이 삭제할 수 있다
- 운영자는 사진을 보지 않는다 ("사진은 빌라 안에서만" 원칙 유지)

### 5.5 가구 상점

- 포인트로 내 종목에 맞는 가구를 사서 방에 배치한다 **[확정]**
- **[제안]** 종목별 가구 5~8개, 공용 가구(식물, 조명 등) 몇 개로 시작
- **[제안]** 방에는 정해진 배치 자리(예: 바닥 3곳, 오른쪽 벽 · 뒷벽 2곳. 왼쪽 벽은 게시판)가 있고 가구를 자리에 끼워 넣는다. 자유 배치는 하지 않는다
- 가구 목록과 가격은 기획자가 확정한다 (시안의 가구명은 예시)

### 5.6 캐릭터 꾸미기

- 간단한 커스터마이징 **[확정]**
- **[제안]** 피부색, 헤어스타일 몇 종, 상의 색. 포인트 없이 무료

### 5.7 도시 지도 (빌라 보기)

- "빌라 보기"를 누르면 가상의 도시를 지도처럼 크게 보여준다 **[확정]**
- 다른 빌라는 구경만 가능하다 **[확정]**
- 다른 빌라에 내 빌라를 보여줄지 켜고 끌 수 있다 **[확정]**

**[확정 — 기획자 결정, 2026-11-19]**
- 빌라 화면 위쪽 **[도시 보기]** 버튼 → 도시 화면(`/city`). 도시는 밤 풍경의 큰 지도이고 화면 나머지는 화이트톤 그대로
- 지도에는 **공개한 빌라만** 건물로 나온다. 해체된 빌라는 나오지 않는다
- 건물 높이 = 빌라에서 가장 높은 층(빌라 화면과 같은 기준: 오늘 7일째를 채우면 바로 한 층 위). 맨 위에 금색 테두리 펜트하우스. 층이 많으면 아파트처럼 높은 건물로 그린다
- 창문은 입주민 한 명에 하나. **오늘(한국 시간) 사진 인증한 입주민 수만큼 불이 켜진다** (지운 사진 · 중복 사진은 세지 않음). 불 꺼진 창은 짙은 남색
- 건물을 누르면 작은 카드 : 빌라 이름, 입주 인원 n/20, 오늘 불 켜진 방 수, 펜트하우스 주인 닉네임. **사진 · 루틴 · 입주민 목록 · 다른 빌라 입주민 id는 보내지도 보여 주지도 않는다** (서버가 숫자만 보낸다)
- 내 빌라는 "우리 빌라" 표시가 붙고, 공개돼 있으면 도시를 열 때 그 자리로 이동한다. 공개 안 됐으면 방장에게는 [지도에 공개하기] 버튼이 있는 안내, 입주민에게는 "방장이 공개하면 지도에 나와요"
- **[확정 — 기획자 결정, 2026-11-19]** 빌라 여러 곳에 살면 사는 빌라 **모두**에 "우리 빌라" 표시가 붙고, 도시를 열면 가장 먼저 입주한 빌라 자리로 이동한다. 지도에 없는 빌라마다 "OO은(는) 아직 지도에 없어요"(방장, [지도에 공개하기]) 또는 "OO은(는) 방장이 공개하면 지도에 나와요" 한 줄. 불 켜진 창 · 가장 높은 층은 그 빌라에 올린 인증 · 그 빌라 층 기준
- 공개 설정은 **방장만** 한다 (설정 → 도시 지도에 공개 스위치, 입주민에게는 지금 상태만 보임). 처음에는 꺼져 있다. 끄면 바로 지도에서 사라진다
- 빈 땅은 가로등 · 나무 · 벤치 · 버스 정류장 · 자판기 · 편의점, 격자 길과 횡단보도, 강 · 언덕 · 달 · 별로 채워 빌라가 하나뿐이어도 비어 보이지 않게 한다
- ~~빈방 모집 글 · 입주 신청은 이번 범위 밖~~ → 아래 "빈방 모집 깃발"로 들어왔다 **[확정 — 기획자 결정, 2026-11-19]**. ~~집값~~(→ 5.11), 위치 이사, 다른 빌라 방 구경은 여전히 범위 밖

**빈방 모집 깃발 [확정 — 기획자 결정, 2026-11-19]**
- 모집 중이고 빈방이 있는 공개 빌라는 지붕 모서리에 주황색 **"모집 중" 깃발**이 꽂힌다(화면 낭독기: "…, 입주자 모집 중"). 모집 중인 빌라가 하나라도 있으면 도시 설명에 "깃발이 꽂힌 빌라는 입주자를 모집하고 있어요"
- 건물 카드에 "입주자 모집 중" 칸: 한 줄 소개, 종목(없으면 "종목 상관없음"), 빈방 n개, 그리고 신청 상태에 따라 [입주 신청] / 신청함 · [신청 취소] / 신청할 수 없는 이유 (5.2 입주 신청)
- 서버는 모집 글과 빈방 수만 더 보낸다. 신청한 사람 정보는 보내지 않는다. 보는 사람이 입주 금지된 빌라면 그 사람에게만 "신청할 수 없음" 표시를 보낸다

**빌라 자리 규칙 [확정 — 기획자 결정, 2026-11-19]**
- 빌라는 **처음 공개할 때** 자리 번호를 받는다: 비어 있는 가장 작은 번호(0부터)
- 공개를 껐다 켜도 **같은 자리**를 지킨다
- 빌라가 해체되면(방장 해체 또는 마지막 입주민이 나감) 자리를 비우고, 다음에 처음 공개하는 빌라가 쓸 수 있다
- 자리 번호는 한 빌라에 하나뿐이다(DB 유일 색인). 번호 고르기와 쓰기는 한 문장으로 해서 동시에 공개해도 두 빌라가 같은 자리를 받지 않는다
- 지도는 자리 번호 순으로 그린다. 다섯 칸마다 한 칸은 공원 · 가게 땅으로 남겨 둔다. 한 번에 앞에서부터 200곳까지 보낸다

### 5.8 화면 목록 [제안]

  - 집값 = **기본 1억(10)** + 입주민 한 명당 **0.1억(1)** + 최근 7일(정산한 날 포함) 동안 입주민이 **이 빌라에 인증한 날** 하루당 **0.1억(1)** + 입주민 층이 1층보다 높은 만큼 한 층당 **0.1억(1)**
  - 예) 9명, 평균 3일 인증, 3명이 2층 → 10 + 9 + 27 + 3 = 4.9억 / 20명 모두 매일 인증, 평균 4층 → 10 + 20 + 140 + 60 = 23억
- 세는 사람: 그날이 끝나기 전에 입주해 지금 사는 입주민. 세는 인증: 그 빌라에 올라간(cert_villas), 지우지 않은 · 중복이 아닌 사진 인증 (4.3 "빌라 V에서 인증한 날"과 같은 정의). 빌라 여러 곳에 사는 사람은 빌라마다 따로 센다. 층은 그날 정산 뒤의 층
- 해체된 빌라 · 입주민이 없는 빌라는 집값이 없다
- 집값은 정산 batch 안에서 날짜 선점(token) 조건으로 함께 쓴다: 층을 바꾼 정산과 집값은 늘 함께 남거나 함께 안 남는다. 밀린 날을 몰아 정산하면 그날들의 집값도 하루씩 남는다
- 화면 표시: "3.2억"(소수 한 자리), 전날과 비교 "▲0.3억"(빨강) / "▼0.2억"(파랑) / "변동 없음". 전날 값이 없으면 비교 없이

**주간 리그**
- 일요일을 정산하는 크론(월요일 0시 KST)이 그 주(월~일, 주 id = 월요일 날짜)의 리그를 매긴다: 공개 · 해체 안 된 빌라를 **일요일 집값** 높은 순으로. 일요일의 "최근 7일"이 곧 그 주다
- **그 주에 인증이 하루도 없는 빌라는 순위에 넣지 않는다** (개발자가 정한 규칙: 혼자 만든 빈 빌라로 보상을 받지 못하게)
- 같은 집값이면 인증한 날 합 → 입주민 수 → 먼저 지은 빌라 순 (순위는 겹치지 않는다)
- 1 · 2 · 3위 빌라: **그 주가 시작되기 전에 입주해 지금도 사는** 입주민에게 100 · 60 · 30P, 건물에 금 · 은 · 동 트로피 (다음 리그 결과가 나올 때까지)
- 순위 줄 · 보상 장부 · 포인트를 한 batch 로 쓰고 그 주 순위가 이미 있으면 아무것도 하지 않는다. 크론이 실패해도 다음 날 최근 2주의 일요일을 다시 본다
- 1~3위 빌라 입주민 모두에게 축하 카드 ("지난주 집값 리그 1위! …"). 이번 주에 들어와 포인트가 없는 사람에게는 "포인트는 다음 기회에"

**1:1 대결**
- 방장이 다른 공개 빌라에 신청한다 (집값 순위 줄 · 도시 건물 카드의 [대결 신청]). 우리 빌라도 공개여야 하고, 내가 방장인 빌라끼리는 안 된다
- 상대 빌라 방장이 받거나 거절한다 (대결 신청 카드 → 대결 화면, 빌라 화면의 대결 줄, 설정 → 집값 대결). **48시간** 안에 답이 없으면 만료
- **빌라 하나는 한 번에 대결 하나** (신청 중 포함, 신청한 쪽 · 받은 쪽 모두). 신청 문장 안에서 양쪽을 다시 보고, 같은 편끼리는 DB 유일 색인이 막는다
- 받으면 **다음 날부터 7일**(KST). 이긴 쪽 = (7일째 집값 − 첫날 전날(받은 날) 집값)이 큰 빌라. 같으면 무승부, 보상 없음
- 이긴 빌라에서 **대결 첫날 전에 입주해 지금도 사는** 입주민에게 50P, 건물에 "대결 승리" 메달 7일
- 어느 한쪽이 해체되거나 지도에서 내려가면 대결 취소, 보상 없음 (공개 끔 · 해체 때 바로, 크론도 매일 확인). 판정에 필요한 날 집값이 빠졌으면 취소
- 신청한 쪽 방장은 상대가 받기 전에 [신청 취소]. 진행 중인 대결은 취소할 수 없다
- 상태: pending → active → finished / pending → declined · expired · cancelled / active → cancelled. 바꾸는 문장은 모두 "지금 상태일 때만" 조건
- 알림: 신청 받음(상대 방장, 카드 → 대결 화면) · 시작(두 빌라 입주민, 토스트) · 거절 · 만료(신청한 방장, 토스트) · 취소(토스트) · 결과(두 빌라 입주민, 승리 · 패배 · 무승부 카드)

### 5.12 아파트 승격 [제안 — 기획자 확인 필요, 2026-11-20]

기획자 부재로 개발자가 정한 기본안이다. 아래 모두 **[제안 — 기획자 확인 필요, 2026-11-20]**

**규칙**
- 입주민 수가 정원(20명)에 다다른 빌라는 **방장이** 아파트로 바꿀 수 있다. **한 방향**이다(다시 빌라로 돌아갈 수 없다)
- 빌라마다 종류(`villas.kind`: `'villa'` · `'apartment'`)와 정원(`villas.capacity`: 빌라 20 · 아파트 50, `APARTMENT_CAPACITY = 50`)을 둔다. `VILLA_CAPACITY = 20` 은 새 빌라의 기본값으로 남는다
- 정원을 쓰는 곳은 모두 그 빌라의 정원을 본다: 초대 링크 입주 · 입주 신청 · 승인(한 문장 안의 정원 검사) · 정원이 차면 모집 끄기 · 모집 켜기 · 도시 카드 "입주 인원 n/정원" · 모집 깃발 빈방 수 · 초대 미리보기 · 빌라 화면 "입주 n/정원명" · 빈방 접기
- 이름은 방장이 지은 그대로. 그 건물의 종류를 부르는 곳만 "아파트"(배지 "아파트", "아파트 정원 50명", "아파트가 꽉 찼어요", 도시 "우리 아파트"). 앱 전체 말(빌라 화면, 빌라 바꾸기 탭, 빌라 3곳 제한, 빌라 나가기)은 "빌라" 그대로. **아파트도 3곳 제한에 하나로 센다**
- 층 · 펜트하우스(건물 전체에 한 명) · 집값 공식(합계라 사람이 많을수록 이미 유리) · 리그 · 대결은 그대로
- 승격해도 모집은 꺼진 채로 둔다(정원이 차서 꺼졌던 것). 방장이 다시 켤 수 있다

**승격 (POST /api/villas/:id/promote)**
- 한 batch: ① `kind = 'villa'` · 해체 안 됨 · `owner_id = 나` · 지금 입주민 수 ≥ 정원일 때만 `kind = 'apartment', capacity = 50` (두 번 눌러도 · 나가기 · 방장 넘기기와 겹쳐도 한 번만) ② 바뀌었을 때만 그때 사는 입주민 모두에게 축하 카드(고정 키 `apartment:{빌라}:{사람}`)
- 응답: 200 `{ ok, kind, capacity }` / 404 빌라 없음 · 해체 / 403 방장 아님 / 409 `{ error, reason: "already" | "not_full", memberCount, capacity }` ("이미 아파트예요" · "입주민이 20명 모여야 아파트로 바꿀 수 있어요 (지금 n명)")

**설정 → 고른 빌라의 "아파트 승격" (집값 대결 아래, 빈방 모집 위)**
- 아파트로 승격 : 버튼, 방장만, 정원이 다 찬 빌라만
  - 신규입력(승격 가능, 방장 · 빌라 · n ≥ 정원) : 진행 막대 + "입주민 20/20명이 다 모였어요! 아파트로 바꾸면 정원이 50명으로 늘어나…" + [아파트로 승격] → 확인 칸 "아파트로 바꾸면 다시 빌라로 돌아갈 수 없어요." (정원 20→50 · 이름 · 층 · 펜트하우스 · 집값 계산은 그대로 · 입주민 모두에게 축하 카드) [아파트로 바꾸기] [취소] → "아파트가 됐어요! 이제 50명까지 함께 살 수 있어요. 빈방 모집도 다시 켤 수 있어요"
  - 수정 : 없음 (되돌릴 수 없다)
  - 읽기전용 : 방장 · 아직 정원이 안 참 → 진행 막대 + "입주민 17/20명 — 20명이 모이면 아파트로 바꿀 수 있어요" / 방장이 아닌 입주민 → "입주민 n/20명 — 20명이 모이면 방장이 아파트로 바꿀 수 있어요"(다 찼으면 "다 모였어요! 방장이 아파트로 바꾸면 정원이 50명으로 늘어요") / 이미 아파트 → 누구나 "[아파트] 우리 아파트예요 · 정원 50명 (지금 n명)"

**화면**
- 축하 카드(입주민 모두): "우리 빌라가 아파트가 됐어요! 이제 50명까지 함께 살 수 있어요" (빌라 2곳 이상 사는 사람에게는 빌라 이름). 그림: 두 팔 벌려 점프 + 색종이, 뒤에 금색 돔을 얹은 아파트(참고 그림 docs/art-reference/v2/apartments.webp 를 집 그림 선 SVG 로 다시 그림)

## 7. 만드는 방식

### 7.1 검토한 방법

| | A. Supabase + Cloudflare Pages | **B. Cloudflare로 전부 (선택)** | C. 기존 호스팅에 공간 추가 |
|---|---|---|---|
| 구성 | Supabase가 로그인 · DB · 사진 · 자정 작업, Cloudflare Pages가 화면 | Pages(화면) + Workers(서버) + D1(DB) + R2(사진) + Cron Triggers(자정 작업) | PHP |
| 무료 한도 | DB 500MB, 사진 1GB | DB 5GB, 사진 10GB, 하루 요청 10만 건 | 공간 추가 비용 가능성 |
| 장점 | 로그인 등이 이미 있어 빠름 | 무료 용량이 가장 넉넉하고, 상업적으로 써도 무료 요금제 유지 | 익숙한 환경 |
| 단점 | 사진 용량이 빨리 참. 1주 미사용 시 일시 정지 | 로그인 · 권한을 직접 구성. R2는 카드 등록이 필요할 수 있음 | 비용, 실시간 · 자정 작업 직접 구현 |

- 제외 : Firebase (무료 요금제에서 사진 저장 · 서버 기능 불가), Vercel (무료 요금제는 비상업 용도만)
- **B를 선택한 이유** : 개발은 Claude가 맡으므로 직접 구성하는 부담이 작다. 실제 서비스로 키우고 후원을 받을 계획이라, 용량이 넉넉하고 상업 이용이 가능한 무료 요금제가 맞다 **[확정]**
- 무료 한도 수치는 작성 시점 기준. 개발 착수 전에 다시 확인한다

### 7.2 기술 구성 [제안]

- 웹앱 (모바일 브라우저 우선, 홈 화면 추가 지원)
- 화면 : Cloudflare Pages
- 서버 : Cloudflare Workers
- DB : Cloudflare D1
- 사진 : Cloudflare R2. 업로드 전에 브라우저에서 긴 변 1280px, 약 150KB로 줄인다
- 자정 작업 : Cron Triggers (인증 확정, 연속 기록 · 층 계산, 펜트하우스 재계산)
- 빌라 · 도시 화면 : 브라우저에서 SVG 또는 Canvas로 그린다
- 디자인 : 화이트톤 **[확정]**

### 7.3 무료 한도 관리 [제안]

- Cloudflare 계정은 기획자(운영자) 본인 명의로 만든다
- 운영자 알림은 Cloudflare 계정의 사용량 알림 기능을 쓴다 (사용자 이메일은 받지 않으므로)
- 사진 저장량이 한도의 80%에 도달하면 운영자에게 알리고, 오래된 사진은 썸네일만 남기는 정책을 적용할지 결정한다
- 90%에 도달하면 앱이 사진 업로드를 막고 안내를 띄운다. Cloudflare에는 지출 상한이 없어서 앱이 직접 막는다
- 1차(10명 기준 추정, 정원 20명이면 약 2배)는 하루 최대 약 30장, 1년에 약 1.6GB 수준이라 한도에 여유가 있다
