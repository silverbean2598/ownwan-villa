## 1. 무엇을 왜 만드나

같이 오운완(오늘 운동 완료)하기로 한 사람들이 **빌라 하나에 입주**해서, 매일 운동 인증 사진과 루틴을 올리고, 받은 포인트로 **자기 방을 운동 종목에 맞는 가구로 꾸미며**, 꾸준히 할수록 **높은 층으로 올라가 펜트하우스를 차지**하는 웹앱이다.

- **누구를 위한 것인가** : 운동을 꾸준히 하고 싶은 사람들 (헬스, 필라테스, 러닝, 클라이밍, 주짓수, 태권도 등)
- **왜** : 혼자 하면 끊기는 운동을, 친구들과 한 건물에 사는 느낌과 눈에 보이는 보상(불 켜진 방, 가구, 층수, 펜트하우스)으로 매일 이어가게 한다
- **운영 목표** : 실제 사람을 모아 운영하는 서비스. 잘되면 후원을 받고 회사 서비스로 키운다 **[확정]**
- **비용 조건** : 지금은 무료 호스팅 범위 안에서만 운영한다 **[확정]**

## 2. 목표 · 비목표 · 실패 조건

**목표 (첫 버전)**
- 초대 링크를 받은 친구가 빠르게 가입하고 빌라에 입주할 수 있다
- 매일 인증 → 포인트 → 가구 → 층 상승 흐름이 끊김 없이 돌아간다
- 빌라 화면에서 오늘 누가 운동했는지(불 켜짐)를 한눈에 본다
- 도시 지도에서 다른 빌라를 구경한다

**비목표 (첫 버전에서 하지 않음)**
- 빌라 간 집값 대결, 아파트 승격, 도시 내 위치 이사, 후원 결제
- 네이티브 앱 (iOS/Android). 웹앱으로 시작한다 **[확정]**
- 소셜 로그인, 이메일 · 전화번호 수집 **[확정]**

**실패 조건 (기능은 돌아가도 실패로 보는 경우)**
- 사진 여러 장 반복 업로드로 포인트를 쉽게 불릴 수 있어 층 · 펜트하우스 경쟁이 무의미해짐
- 인증 사진이 빌라 밖으로 노출됨
- 무료 한도를 넘어 비용이 발생함 (사전 경고 없이)
- 가입이 번거로워 초대받은 친구가 중간에 이탈함

## 3. 용어

| 용어 | 뜻 |
|---|---|
| 빌라 | 최대 10명이 함께 사는 모임 단위 |
| 방장 | 빌라를 만든 사람 |
| 방 | 입주민 한 명의 공간. 종목에 맞게 꾸며짐 |
| 층 | 입주민 개인의 레벨. 사람마다 따로 매김 |
| 펜트하우스 | 빌라 1등 한 명이 사는 최상층 |
| 오운완 인증 | 그날 운동 사진을 1장 이상 올린 것 |
| 연속 기록 | 하루도 빠지지 않고 인증한 일수 |
| 도시 | 공개된 빌라들이 모여 있는 가상의 지도 |

## 4. 핵심 규칙

### 4.1 하루의 기준
- **[제안]** 하루는 한국 시간 00:00 ~ 23:59. 자정에 그날 인증 여부를 확정하고 층 · 순위를 다시 계산한다

### 4.2 인증과 포인트
- 사진 1장만 올려도 오늘 인증으로 인정된다 **[확정]**
- 많이 올릴수록 포인트를 더 준다 **[확정]**
- **[제안]** 추가 사진은 보너스가 줄어들고 하루 상한이 있다

| 항목 | 포인트 (예시) |
|---|---|
| 첫 번째 사진 (오늘 인증) | 20P |
| 두 번째 사진 | 10P |
| 세 번째 사진 | 5P |
| 네 번째 이후 | 0P (기록만 남음) |
| 루틴 글 작성 (하루 1회) | 10P |
| 하루 최대 | 45P |

- **[제안]** 이전에 올린 사진과 같거나 거의 같은 사진은 포인트를 주지 않는다 (업로드 시 이미지 유사도 비교)
- **[제안]** 인증 사진은 그날 촬영 여부를 검사하지 않는다. 첫 버전에서는 유사도 비교와 빌라 내 신고로 대응한다

### 4.3 층
- 7일 연속 인증 달성 시 한 층 올라간다 **[확정]**
- 연속 기록이 끊기면 한 층 내려간다 **[확정]**
- **[제안]** 세부 규칙
  - 입주 시 1층에서 시작한다
  - 연속 기록 7일, 14일, 21일… 달성 시점마다 +1층
  - 인증을 하루 빠뜨리면 연속 기록은 0이 되고 즉시 -1층
  - 그 뒤로도 인증하지 않으면 7일마다 1층씩 더 내려간다 (오래 쉬면 계속 내려감)
  - 최저층은 1층
  - 층에는 상한이 없다

### 4.4 펜트하우스
- 빌라에서 1등 한 명만 산다 **[확정]**
- **[제안]** 1등 판정 순서
  1. 층이 가장 높은 사람
  2. 층이 같으면 현재 연속 기록이 긴 사람
  3. 그것도 같으면 그 층에 먼저 도달한 사람
- **[제안]** 1등은 자정에 다시 계산하고, 바뀌면 그때 이사한다. 밀려난 사람은 자기 층의 방으로 돌아간다
- **[제안]** 펜트하우스에는 전용 장식(샹들리에, 통유리창 등)이 고정되어 있다. 개인 가구는 사람을 따라 이사한다
- **[제안]** 입주민이 1명뿐이어도 그 사람이 펜트하우스에 산다

### 4.5 방 상태
- 오늘 인증한 방은 불이 켜지고, 캐릭터가 방 안의 기구로 운동한다 **[확정]**
- 오늘 인증하지 않은 방은 불이 꺼져 있다 **[확정]**
- **[제안]** 불 꺼진 방의 캐릭터는 자고 있다

## 5. 기능 상세 (첫 버전)

### 5.1 회원가입 · 로그인 · 계정 복구 [확정]

받는 정보는 **아이디, 비밀번호, 닉네임**뿐이다. 이메일 · 전화번호는 받지 않는다.

**회원가입 필드**
- 아이디 : 텍스트입력, 빈값, -, 필수 (영문 소문자·숫자 4~16자, 중복 확인)
- 비밀번호 : 비밀번호입력, 빈값, -, 필수 (8자 이상)
- 비밀번호 확인 : 비밀번호입력, 빈값, -, 필수
- 닉네임 : 텍스트입력, 빈값, -, 필수 (빌라에서 보이는 이름, 2~10자)
- 만 14세 이상 확인 : 체크박스, 미체크, -, 필수
- 이용약관 · 개인정보 처리방침 동의 : 체크박스, 미체크, -, 필수

**복구 코드 (기본 수단)**
- 가입 완료 시 복구 코드(예: `K7QM-2XPA-9RTE-W4LN`)를 한 번만 보여준다. 복사 · 이미지 저장 버튼 제공
- "복구 코드를 저장했어요" 체크 후에만 다음 단계로 이동
- 비밀번호 분실 시 아이디 + 복구 코드 입력 → 새 비밀번호 설정 → 새 복구 코드 발급 (기존 코드는 폐기)
- 로그인 상태에서 설정 화면에서 복구 코드를 재발급할 수 있다 (재발급 시 기존 코드 폐기)
- 서버에는 복구 코드를 해시로만 저장한다

**방장 확인 (보조 수단)**
1. 로그인 화면 "복구 코드도 없어요" → 아이디 입력
2. 해당 사용자가 사는 빌라의 방장에게 복구 요청 알림
3. 방장이 본인 여부를 직접(빌라 밖 연락 수단으로) 확인 후 승인
4. 승인 후 24시간 대기. 대기 중 원래 사용자가 로그인하면 요청 자동 취소
5. 24시간 후 요청자가 아이디 + 복구 요청 번호로 새 비밀번호 설정
- 요청자가 방장이면, 빌라에 가장 오래 산 입주민이 확인한다
- **[제안]** 빌라에 속하지 않은 사용자(입주 전)는 방장 확인을 쓸 수 없다

**보안 [제안]**
- 비밀번호는 검증된 해시 방식으로만 저장한다. 로그인 · 세션은 검증된 라이브러리를 사용한다
- 로그인 실패가 연속되면 일정 시간 잠금 (무차별 대입 방지)

### 5.2 빌라

- 정원 약 10명 **[확정]** → **[제안]** 10명으로 고정
- 입주 경로 2가지 **[확정]**
  - 초대 링크 : 방장이 만든 링크로 입주
  - 빈방 모집 : 빈방에 모집 글을 올려 같이 운동할 사람을 모음
- 빌라 이름은 방장이 정한다 **[확정]**
- **[제안]** 방장 권한 : 빌라 이름 변경, 초대 링크 생성 · 재생성, 빈방 모집 글 작성, 도시 공개 설정, 계정 복구 승인
- **[제안]** 강퇴, 수동 방장 위임, 빌라 해체는 첫 버전에서 제외 (다음 버전에서 정의)

**빌라 나가기 · 옮기기 [확정]**
- 첫 버전에 "빌라 나가기"를 넣는다
- 사용자는 빌라 1곳에만 산다 **[제안]**
- 빌라를 옮기면 **연속 기록, 포인트, 가구, 캐릭터는 가져가고, 층만 1층부터 다시 시작한다**
  - 이유 : 내가 쌓은 습관은 남기고, 새 빌라의 순위는 흔들지 않는다
  - 따라서 연속 기록 · 포인트 · 가구는 사용자에게, 층은 빌라 입주 기록에 붙는다
- **[제안]** 빌라를 나가면 그 방은 빈방이 되고, 인증 사진 · 루틴은 원래 빌라에서 더 이상 보이지 않는다
- **[제안]** 빌라가 없는 상태에서도 인증은 할 수 있고 연속 기록이 이어진다. 층은 없다
- **[제안]** 방장이 나가면 그 빌라에 가장 오래 산 입주민이 자동으로 방장이 된다. 마지막 한 명이 나가면 빌라는 도시에서 사라진다
- **[제안]** 나가기 전에 "층은 1층부터 다시 시작해요" 확인 화면을 보여준다

**빈방 모집 [제안]**
- 모집 글은 도시 지도의 해당 빌라에서 보이고, 빌라를 눌러 입주 신청할 수 있다
- 입주 신청은 방장이 승인한다

### 5.3 방 · 종목

- 입주 시 "어떤 운동을 하시나요?"를 묻는다 **[확정]**
- 종목 : 헬스 / 필라테스 / 러닝 / 클라이밍 / 주짓수 / 태권도 **[확정, 이 외 종목은 기획자가 추가 확정]**
- 선택한 종목에 맞는 소품 몇 개로 꾸며진 방에서 시작한다 **[확정]**
- **[제안]** 종목 변경은 설정에서 가능하다. 이미 산 가구는 유지된다

**종목 선택 필드**
- 운동 종목 : 단일선택(카드형), 미선택, 헬스/필라테스/러닝/클라이밍/주짓수/태권도, 필수 **[확정]**
  - 신규입력 : 선택 가능
  - 수정 : 설정 화면에서 변경 가능
  - 읽기전용 : 다른 입주민의 방 상세에서 표시만

### 5.4 인증 · 루틴

- 사진 업로드 (1장 이상), 루틴 글 (선택)
- 인증 사진과 루틴은 **같은 빌라 사람들끼리만** 본다 **[확정]**

**방 게시판 [확정]**
- 모든 방의 **왼쪽 벽은 늘 게시판**이다. 가구를 놓는 자리가 아니라 고정 요소다
- 올린 오운완 사진과 루틴이 게시판에 붙는다
- **[제안]** 게시판에는 최근 것부터 사진은 폴라로이드처럼, 루틴은 메모지처럼 붙는다. 방 화면에서는 최근 몇 개만 보이고, 게시판을 누르면 전체 기록을 날짜순으로 본다
- **[제안]** 같은 빌라 입주민은 다른 사람 방에 들어가 그 사람의 게시판을 볼 수 있다

**신고 [제안]**
- 같은 빌라 입주민이 부적절한 사진을 신고할 수 있다
- 3명이 신고하면 사진이 자동으로 가려지고, 방장이 삭제할 수 있다
- 운영자는 사진을 보지 않는다 ("사진은 빌라 안에서만" 원칙 유지)

### 5.5 가구 상점

- 포인트로 내 종목에 맞는 가구를 사서 방에 배치한다 **[확정]**
- **[제안]** 종목별 가구 5~8개, 공용 가구(식물, 조명 등) 몇 개로 시작
- **[제안]** 방에는 정해진 배치 자리(예: 바닥 3곳, 오른쪽 벽 · 뒷벽 2곳. 왼쪽 벽은 게시판)가 있고 가구를 자리에 끼워 넣는다. 자유 배치는 하지 않는다
- 가구 목록과 가격은 기획자가 확정한다 (시안의 가구명은 예시)

### 5.6 캐릭터 꾸미기

- 간단한 커스터마이징 **[확정]**
- **[제안]** 피부색, 헤어스타일 몇 종, 상의 색. 포인트 없이 무료

### 5.7 도시 지도 (빌라 보기)

- "빌라 보기"를 누르면 가상의 도시를 지도처럼 크게 보여준다 **[확정]**
- 다른 빌라는 구경만 가능하다 **[확정]**
- 다른 빌라에 내 빌라를 보여줄지 켜고 끌 수 있다 **[확정]**
- **[제안]** 공개 설정은 방장이 한다. 꺼 두면 지도에 나타나지 않는다
- **[제안]** 구경할 때 보이는 것 : 빌라 이름, 건물 높이, 펜트하우스, 오늘 불 켜진 방 수, 빈방 모집 여부. 사진 · 루틴은 보이지 않는다
- **[제안]** 도시는 밤 풍경. 오늘 인증한 사람이 많은 빌라일수록 창문 불이 많이 켜져 있다
- **[제안]** 빌라 위치는 만들 때 빈 자리에 배정한다

### 5.8 화면 목록 [제안]

1. 첫 화면 (서비스 소개, 로그인 / 가입)
2. 회원가입 → 복구 코드 저장
3. 로그인, 비밀번호 찾기 (복구 코드 / 방장 확인)
4. 빌라 만들기 또는 초대 링크로 입주
5. 종목 선택 → 캐릭터 꾸미기
6. 빌라 화면 (메인)
7. 방 상세 (왼쪽 벽 게시판, 가구, 캐릭터)
8. 오늘 인증하기 (사진 업로드, 루틴 작성)
9. 가구 상점 · 배치
10. 도시 지도, 다른 빌라 구경
11. 설정 (종목, 캐릭터, 비밀번호, 복구 코드, 빌라 나가기, 방장 메뉴)

### 5.9 알림 · 화면 갱신 [제안]

- 알림은 앱 안의 배지로만 한다 (방장 승인 요청, 계정 복구 요청, 입주 신청). 매일 인증하러 들어오는 서비스라 충분하다고 본다. 웹 푸시는 다음 버전
- 빌라 화면은 실시간이 아니라 화면을 열거나 새로고침할 때 반영한다. 무료 요청 한도를 아낀다

## 7. 만드는 방식

### 7.1 검토한 방법

| | A. Supabase + Cloudflare Pages | **B. Cloudflare로 전부 (선택)** | C. 기존 호스팅에 공간 추가 |
|---|---|---|---|
| 구성 | Supabase가 로그인 · DB · 사진 · 자정 작업, Cloudflare Pages가 화면 | Pages(화면) + Workers(서버) + D1(DB) + R2(사진) + Cron Triggers(자정 작업) | PHP |
| 무료 한도 | DB 500MB, 사진 1GB | DB 5GB, 사진 10GB, 하루 요청 10만 건 | 공간 추가 비용 가능성 |
| 장점 | 로그인 등이 이미 있어 빠름 | 무료 용량이 가장 넉넉하고, 상업적으로 써도 무료 요금제 유지 | 익숙한 환경 |
| 단점 | 사진 용량이 빨리 참. 1주 미사용 시 일시 정지 | 로그인 · 권한을 직접 구성. R2는 카드 등록이 필요할 수 있음 | 비용, 실시간 · 자정 작업 직접 구현 |

- 제외 : Firebase (무료 요금제에서 사진 저장 · 서버 기능 불가), Vercel (무료 요금제는 비상업 용도만)
- **B를 선택한 이유** : 개발은 Claude가 맡으므로 직접 구성하는 부담이 작다. 실제 서비스로 키우고 후원을 받을 계획이라, 용량이 넉넉하고 상업 이용이 가능한 무료 요금제가 맞다 **[확정]**
- 무료 한도 수치는 작성 시점 기준. 개발 착수 전에 다시 확인한다

### 7.2 기술 구성 [제안]

- 웹앱 (모바일 브라우저 우선, 홈 화면 추가 지원)
- 화면 : Cloudflare Pages
- 서버 : Cloudflare Workers
- DB : Cloudflare D1
- 사진 : Cloudflare R2. 업로드 전에 브라우저에서 긴 변 1280px, 약 150KB로 줄인다
- 자정 작업 : Cron Triggers (인증 확정, 연속 기록 · 층 계산, 펜트하우스 재계산)
- 빌라 · 도시 화면 : 브라우저에서 SVG 또는 Canvas로 그린다
- 디자인 : 화이트톤 **[확정]**

### 7.3 무료 한도 관리 [제안]

- Cloudflare 계정은 기획자(운영자) 본인 명의로 만든다
- 운영자 알림은 Cloudflare 계정의 사용량 알림 기능을 쓴다 (사용자 이메일은 받지 않으므로)
- 사진 저장량이 한도의 80%에 도달하면 운영자에게 알리고, 오래된 사진은 썸네일만 남기는 정책을 적용할지 결정한다
- 90%에 도달하면 앱이 사진 업로드를 막고 안내를 띄운다. Cloudflare에는 지출 상한이 없어서 앱이 직접 막는다
- 1차(10명)는 하루 최대 약 30장, 1년에 약 1.6GB 수준이라 한도에 여유가 있다
